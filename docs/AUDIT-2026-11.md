# GMusic 改造版 点検報告（2026-11）

対象: 本番（main・pve）で動いている **GMusic-1.3.0.jar** と、リポジトリの `main`（4883396「パーミッションチェック修正 (v1.2.2)」）
修正ブランチ: `claude/gmusic-130-restore`。2 段に分けてあります:

1. **本番の 1.3.0 をソースに復元**（版 1.3.0）。本番の jar と中身が同じになるコミット
2. **点検で見つけた問題の直し**（版 1.3.1）

## 0. 準備で分かったこと

- **upstream（gecolay/GMusic）** は 2.0.0 で全面的に書き直されています（`object/` → `model/`、`GMusicGUI` → `MusicGUI` など、パッケージとクラス名が変わった）。53 コミットをまとめて取り込むと改造部分がほぼ全部ぶつかるため、**必要な直しだけを手で移しました**。
- upstream の 26.x 対応の要点は、(1) 版の読み取りを `getVersion()` の `MC: x.y.z` から行う、(2) 版の比較をすべての桁で行う（26.x を 1.x より新しいと判定する）、(3) 26.1・26.2・26.3 の mcv モジュールの追加、の 3 つです。追加された mcv の `MusicInputGUI` は、1.21.6 版と**パッケージ名の行以外は同じ**です。26.x は Mojang の名前のまま配布されるため、Mojang 名でビルドしてある既存の `v1_21_6` の実装がそのまま使えます。
- upstream も再生には `java.util.Timer`（1ms 周期）を使っています。音の時刻を 1ms 単位で合わせるための作りなので、改造版でもこの方式は残しました。そのうえで、**別スレッドからワールドを走査しない・GUI を触らない・DB を読まない** 形に直しました。
- Paper 26.x の API の変化について、公式の移行メモは見つけられませんでした。この点検は upstream の 26.x 対応の差分と、手元のコード読みに基づいています。

**1.3.0 で main に足されていたもの**（このブランチの 1 つ目のコミットでソースに戻した）:

1. 26.x 対応: 版を `getVersion()` の `MC:` から読み、全部の桁で比べる。26.1 系は `v1_21_6` に割り当て、26.2 も `v1_21_6` に落ちて動く
2. PlaceholderAPI 連携（softdepend）: `%gmusic_playing_title%` など 10 個
3. `/music favorite`（再生中の曲をお気に入りに入れる・外す）、`/music loop on|off`、補完と ja_jp・en_us の文言
4. GUI の検索ボタン（望遠鏡・スロット 50）、管理者でない人のスピーカー範囲を既定の範囲までに制限
5. ジュークボックス: 音量の減衰を直線から二乗に、ミュートしている人にはアクションバーを出さない、置いたときに設定を保存
6. ラジオ: 聞き手を `CopyOnWriteArraySet` に、タイマーの中の例外で止まらないように
7. `GPlayListMode.byId` は、見つからないとき `null` ではなく `DEFAULT` を返す

**復元が正しいことの確認**: 1 つ目のコミットで作った jar は、**72 クラスすべてが本番の jar と命令の単位で一致**します（`javap -c -p -constants` で比較）。`plugin.yml`・`config.yml`・言語ファイル・`data.yml` もバイト単位で一致しました。jar のサイズの違い（17 B）は、zip の日付と圧縮の差だけです。

## 2. 点検の表

重さ: **高** = 止まる・データが消える・サーバーが重くなる／**中** = 条件しだいで壊れる／**低** = 不便・小さな漏れ

| # | 問題 | 重さ | 直したか |
|---|---|---|---|
| 1 | **main のソースは 26.x で起動しない**: `isNewerOrVersion(18, 0)` が版の 2 番目の数字しか見ておらず、「26.2」を「1.2」扱いして無効化する。**Paper 26.2（build 135）で実際に試し、Enabling の直後に Disabling になることを確かめた**。本番の 1.3.0 はこれを直してある | 高 | ✅ 1.3.0 の直しを戻した（1 つ目のコミット）。1.3.1 ではさらに `MC:` が取れない場合の読み方を固め、試験を付けた |
| 2 | **「再生中」アクションバーを 1ms ごとに送っていた**（1.3.0 も同じ）（1 人あたり毎秒 1000 回。そのたびに MiniMessage の解析と送信）。ラジオでも同じ。初期設定で有効（`show-while-playing: true`） | 高 | ✅ 1 秒に 1 回にした（表示は途切れない） |

| 4 | 再生スレッドとメインスレッドが同じ `HashMap`（再生状態・設定キャッシュ・ジュークボックス・GUI・ラジオの聞き手）を同時に触っていた。HashMap は同時に書くと中身が壊れることがある | 高 | ✅ `ConcurrentHashMap` などに変えた。お気に入りの一覧も `CopyOnWriteArrayList` にした |

## 3. 試験とビルド

### 実際の Paper 26.2 での起動試験

Paper 26.2 build 135（`paper-26.2-135.jar`）と Java 25.0.5 で、それぞれ起動 → `plugins` → `version GMusic` → `gmusicreload` → `stop` を試しました。

| jar | 結果 |
|---|---|
| main の 1.2.0 | ✕ `Enabling GMusic v1.2.0` の直後に `Disabling`（自分で無効化） |
| 本番の 1.3.0 | ○ 有効（緑）、終了まで例外なし |
| 今回の 1.3.1 | ○ 有効（緑）、リロードも終了も例外なし |
| 1.3.0 の DB のまま 1.3.1 に入れ替え | ○ `uniformRadius` 列が自動で足され、既存の行とお気に入りは残った |

クライアントで実際に入って音を聞く試験は、ここではできていません（beta で確かめてください）。

### 単体試験

- 追加した試験（`core/src/test`、JUnit 5）:
  - `VersionServiceTest`: 26.2・26.1.2・1.21.4 の読み取り、`-` の無い版文字列、26.x を 1.18 以上と判定すること
  - `PlayServiceTest`: アクションバーが 1 秒に 1 回になること
  - `DataServiceTest`（SQLite のメモリ DB）: 保存の途中で失敗してもお気に入りが残ること、文が閉じること
  - `GPlaySettingsTest`: 見つからないお気に入りが保存に残ること、重複しないこと、走査中に追加しても落ちないこと
- MockBukkit は使っていません。プラグイン全体を起動するには mcv の NMS クラスが要るため、純粋な部分を切り出して試験しています。
- GitHub Actions: `.github/workflows/build.yml` を追加しました。push・PR のたびに全モジュールをビルドし、試験を回し、jar を成果物として 14 日間置きます（Release は作りません）。

## 4. 入れ替えの手順と戻し方（本番の 1.3.0 → 1.3.1）

### 入れ替え（まず beta で）

1. この PR の Actions の成果物（または手元でビルドした `build/libs/`） `GMusic-jar` から `GMusic-1.3.1.jar` を落とします。
2. サーバーを止める前に、`plugins/GMusic/data/` を丸ごと控えます（`data.db` と `data.yml`）。
3. 停止 → `plugins/GMusic-1.3.0.jar` を `plugins/` の外へ移す → `GMusic-1.3.1.jar` を置く → 起動。
4. 確かめること:
   - 起動ログに GMusic の「enabled」が出ること（26.2 で「対応外の版」と出ないこと）
   - `/music` で GUI が開く、曲が鳴る、スピーカーモードで近くの人に聞こえる
   - お気に入りを付けて抜けて入り直し、残っていること
   - ジュークボックスを置いて鳴らし、範囲外に出て戻ると聞こえること
   - spark で `GMusic-play` スレッドと main の MSPT を、入れ替え前と比べる
5. beta で問題が無ければ pve → main の順に同じ手順で入れ替えます。hub（1.2.0）は 1.21 系なら同じ jar で動きます。

DB は列が 1 つ増えるだけ（`uniformRadius`、自動で追加）で、古い版でもそのまま読めます。

### 戻し方

1. 停止 → `GMusic-1.3.1.jar` を外す → 控えておいた `GMusic-1.3.0.jar` を戻す → 起動。
2. 増えた `uniformRadius` 列は古い版から無視されるので、DB を戻す必要は通常ありません。お気に入りがおかしいときだけ、手順 2 で控えた `data/` を戻してください。
